## Rules for using references

1. Extract techniques, not visual identity.
2. Prefer the existing repository architecture when it already solves the same problem.
3. Test every imported pattern against the Stitch palette and zero-radius structural language.
4. Do not introduce effects merely because a reference contains them.
5. Keep accessibility, mobile degradation, and performance as first-class constraints.
